# حزمة ويندوز وبروفة الموبايل — 2026-10-28

تحديث: أُضيف مثبّت EXE وواجهة تشغيل دون CMD وصفحة تنزيل من الموقع. راجع [تطبيق مقدّم ويندوز](29-Windows-Presenter-App.md). التفاصيل أدناه توثّق حزمة ZIP السابقة وتجربتها.

اسم البرانش الآن `production` بناءً على طلب المستخدم. لا توجد دعوة لنشر بوست الآن.

## التنزيل والتشغيل

أصبح لدينا حزمة محلية محمولة Windows x64. الأمر `pnpm lan:package` يجهز مجلداً جديداً داخل releases بعد بناء LAN. يحتوي node.exe وخادم ESM مجمّع بواسطة esbuild، الصفحات والخطوط والصور المحلية، ورخص التوزيع. لا يحتوي أسرار Cloudflare أو Cloudinary، ولا مسابقاتك أو نتائجك. المحرك المستخدم Node 24.11.1، وترخيصه الرسمي من https://raw.githubusercontent.com/nodejs/node/v24.11.1/LICENSE.

المقدّم ينزّل ZIP ويفكّه كاملاً في مجلد عادي قابل للكتابة مثل Documents/Brio. ثم ينقر مرتين Start-Brio.cmd الموجود داخله، فيفتح localhost:3210/local. لا يفتح CMD يدوياً ولا يثبت Node أو pnpm ولا ينسخ ملف التشغيل وحده. لا يشغّل الملف من نافذة معاينة ZIP. الحزمة غير موقعة؛ لا تطلب تجاوز تحذيرات الحماية، وتحقق من المصدر بدلاً من ذلك.

الهواتف لا تشغّل CMD؛ تتصل بنفس الراوتر وتدخل QR. تنزيل الحزمة وتشغيلها يخص المقدّم على لابتوب Windows x64 فقط. macOS وLinux وARM وهواتف Android/iOS غير مدعومة كمضيف بهذه الحزمة. يبقى بإمكانها المشاركة كمتصفح لاعب.

الحزمة تفتح مثالاً جاهزاً فيه صورة. لمسابقاتك نزّل حزمة المسابقة من الموقع مسبقاً واستوردها. بياناته تُحفظ في .brio-lan داخل المجلد المستخرج، وتبقى خاصة بالمقدّم. لا تعيد توزيع مجلد سبق استخدامه: أعد بناء حزمة نظيفة حتى لا تشارك الإجابات أو النتائج. احتفظ بمجلدك القديم للنتائج عند تحديث التطبيق.

ملف ZIP متاح كمخرج محلي لهذه المهمة. رابط تحميل عام مستضاف لم يُنشأ بعد؛ يمكن لاحقاً رفع الملف النظيف كـGitHub Release أو إلى استضافة تنزيلات مناسبة. رابط الموقع السحابي ليس رابط تنزيل الحزمة تلقائياً.

## الدليل الحالي

- شغّلنا النسخة المجمّعة باستخدام runtime/node.exe وruntime/server.mjs دون tsx أو pnpm، واشتغل الخادم وبيانات المثال من الحزمة. لم نختبر Windows نظيفاً لا يحتوي أدوات تطوير؛ يجب اختبار الحزمة عليه أيضاً.
- بروفة ثلاثة contexts منفصلة في Edge/Chromium بعروض 320 و360 و390، مع لمس ومحاكاة موبايل وحجب كل الطلبات خارج origin المحلي.
- استوردنا صورة raster حقيقية، انضم ثلاثة لاعبين، بدأ المضيف عبر WebSocket، ظهرت الصورة وفُك ترميزها، ضغط كل لاعب إجابته من الواجهة، وثبتت 3 إجابات في SQLite.
- انقطع اتصال context واحد ثم عاد وعمل reload؛ بقي عدد اللاعبين 3 وإجاباتهم محفوظة. وصلت اللعبة FINISHED. لا overflow، صفر page errors وصفر طلبات خارجية. الصور mobile-rehearsal-0.png إلى mobile-rehearsal-2.png.
- تقدم وقت الخادم في harness لتسريع المراحل؛ هذا اختبار سلوك وليس قياس latency أو load حقيقي. لم نحاكِ تأخير الصور أو فقد حزم الراديو.
- بعد تعديل مسار التشغيل مرّت TypeScript و9 اختبارات LAN بما فيها 150 WebSocket loopback. لا تعتبر هذه 150 هاتفاً.

لا تتوفر هواتف فعلية للتحكم بها من هذه الجلسة. ما بقي للاختبار الميداني: Android Chrome وiOS Safari حقيقيان على الراوتر، فصل WAN وتعطيل mobile data، السكون والخلفية واستعادة الاتصال، واختبار client isolation وWindows Firewall. التفاصيل في docs/25-Operations-and-Offline.md. محاكاة حجم iPhone في Chromium ليست اختبار Safari.
