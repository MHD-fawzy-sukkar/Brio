# Nonblocking question ordering and creator caching

Each quiz has an account-scoped serial write queue that outlives the studio component. Drag and keyboard moves apply immediately to visible data and the memory cache, while intermediate pending positions coalesce to the latest order. A server response never disables further dragging or rolls back a newer position. Failure retains the desired order with a retry action; starting, exporting or deleting flushes outstanding work first. A before-unload guard covers unsaved orders. Queues cannot send subsequent writes after the account scope changes. Pending optimistic snapshots are not persisted as confirmed data, and successful acknowledgement reapplies the confirmed order while preserving updated image/title fields.

Resource changes now notify only subscribers for affected keys. Quiz mutations invalidate the summary list and that quiz, preserving other details. Reordering owns its cache and no longer triggers broad refetches. Optimistic changes supersede older reads, including forced refreshes during a pending order. Memory entries are bounded to 40; up to 16 same-account session snapshots (500 KB total) remain available for 30 minutes, with stale background refresh. Library freshness is five minutes; other creator data stays at one minute. Logout still clears private data and late responses from previous accounts cannot populate the cache. Next document/RSC cache protections remain in place.

Library prefetch fetches only the theme summaries needed by the chooser. The studio prefetches the first three question images, and later question/dashboard/identity-card images use native lazy loading. Saving a question updates its cached detail and summary before returning to the studio. A late background read cannot replace text the user has started editing.

Validation: 65 frontend tests pass plus two worker reorder integration tests. Cases cover serial coalescing, obsolete failures, explicit retry, route reuse, owner changes, stale image/detail merges, targeted notifications, transient snapshots and retained stale data. Browser testing used an 8-second save delay: three rapid moves produced two writes, grips stayed enabled, navigation to the dashboard and back preserved the final order with no extra detail GET, and editing opened immediately from cache. Two actual pointer drags were also accepted during a delayed save. Production build passes.
