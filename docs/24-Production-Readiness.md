# مراجعة تجهيز الإصدار — 2026-10-28

البرانش النهائي: `codex/production-ready`، مبني من `main` الذي يحتوي تاريخ LAN والثيمات واللغات. لم نحتاج دمجاً جديداً ولم نحذف البرانشات السابقة. هذه مراجعة للكود وفحوص محلية، وليست شهادة أمان أو إثبات اختبار شبكة فعلية.

## إصلاحات مهمة

- رفض Origin الخارجي عند ترقية WebSocket حتى لو كانت GET، وفحص موحد للطلبات المعدّلة بما فيها logout ورفع الصور.
- اتصال اللاعب يتطلب كوكي HttpOnly لجلسة اللاعب الصحيحة، وفحص SHA-256 مقابل المخزن. لا نضع التوكن ضمن URL أو سجلات الطلبات.
- أوامر المضيف تتطلب دور المضيف، وتُراجع صلاحية جلسة المنشئ في D1 عند كل أمر؛ الجلسة الملغاة أو المنتهية لا تتحكم باللعبة.
- الإجابة تؤخذ هوية صاحبها من وسوم الاتصال؛ رفض انتحال لاعب آخر ورفض اتصال تجاوزه اتصال أحدث. تُحفظ generation في SQLite.
- نتائج اللاعب تتطلب جلسة اللاعب، ونتائج المضيف ومقاييس الغرفة تتطلب ملكية الغرفة. ملفات LAN التي تحتوي مفاتيح الإجابات تبقى خاصة بالمقدّم.
- حد 200 لاعب يُفرض داخل الكائن المسؤول عن الغرفة. أجسام API محدودة بـ2 MiB، وWebSocket يحتفظ بحد 4 KiB و10 رسائل/ثانية.
- منع تفعيل development bypass على عنوان سحابي، والتحقق من خوارزمية Google JWT والحقول الأساسية، وكوكي Secure على HTTPS.
- إنهاء رفع الصور يتحقق من معرف الملف الخاص بالمالك وتوقيع Cloudinary ونسخته؛ لم يعد يقبل معرف صورة عشوائياً. تحقق الهوية المخصصة موجود أيضاً.
- تحديث Next/React/Hono/ws وZod، وتكييف API لـZod 4، وتثبيت إصلاحات PostCSS/source-map-js عبر overrides في pnpm-workspace.yaml.
- عناوين صفحات بالعربية والإنكليزية، وصف يوضح شروط LAN، وOpen Graph/Twitter للرابط. إضافة CSP ورفض embedding وnosniff وreferrer policy ومنع فهرسة صفحات اللعب الخاصة.
- حفظ معرف الغرفة المنطقي حتى بعد استيقاظ Durable Object، بدلاً من استبداله بمعرف التخزين الداخلي.

## ما تحقق وما بقي

159 اختباراً مرّت في المجموع: contracts 6، core 10، Worker 61، web 73، LAN 9. تشمل اختبارات أمنية جديدة ومحاكاة اللعبة واختبارات SQLite وHTTP/WebSocket المحلية. فحص `pnpm audit --prod` بعد التحديث: صفر ثغرات معروفة. `wrangler deploy --dry-run` نجح مع الربط الجديد؛ لا ينشر شيئاً.

بناء الإنتاج `pnpm build` وبناء `pnpm lan:build` نجحا بعد إعادة البناء خارج العزل الذي منع إنشاء ملفات بـEPERM. فحص Edge بعرض 375px مع حجب الطلبات الخارجية على قاعدة LAN منفصلة أظهر المسابقة التجريبية والعنوان الصحيح، دون overflow أو أخطاء JavaScript أو طلبات خارجية؛ الصورة release-lan-mobile.png. هذا فحص لوحة LAN وليس إكمال لعبة من هواتف فعلية. لا تعتبر dry-run إثبات نشر الإصدار أو عمل OAuth الحقيقي. لا يوجد اختبار اختراق مستقل أو قياس 150 هاتفاً على شبكة فعالية. الأدلة التاريخية للعب بالمتصفح مع حجب الإنترنت في docs/14-LAN.md منفصلة عن فحوص هذا الإصدار.

## خطوات النشر

1. افحص أن لا توجد فعالية سحابية نشطة. تغيير مصادقة sockets يتطلب إعادة دخول اللاعبين في الغرف القديمة.
2. احفظ رقم آخر deploy وصدّر D1 أو تأكد من إمكانية الاستعادة قبل تطبيق migrations. بناء LAN لا ينشر السحابة.
3. `pnpm install --frozen-lockfile` ثم `pnpm quality` ثم `pnpm lan:build`، بالتتابع.
4. تأكد من Google origins وGOOGLE_CLIENT_ID وNEXT_PUBLIC_GOOGLE_CLIENT_ID ومن أسرار Cloudinary في Cloudflare. أبقِ DEV_AUTH_BYPASS وDEV_MEDIA_BYPASS معطّلين.
5. من apps/worker: `pnpm exec wrangler d1 migrations list brio-db --remote`؛ طبّق فقط الترحيلات المطلوبة عبر `pnpm exec wrangler d1 migrations apply brio-db --remote` بعد النسخة الاحتياطية. هذا الإصدار لا يضيف migration جديدة.
6. `pnpm exec wrangler deploy --dry-run` ثم `pnpm exec wrangler deploy` عند قرار النشر. استخدم ملف القفل وتعريفات Cloudflare المتوافقة مع Wrangler 4.
7. افحص `/api/health`، JSON 404 لمسار API مجهول، و401 للموارد المحمية دون جلسة. افحص CSP/كوكي Secure وعدم تخزين نتائج المستخدم في cache. افتح Google login الحقيقي ورفع صورة ثم غرفة تجريبية على جهازين.
8. جرّب معاينة الرابط في LinkedIn Post Inspector بعد النشر. صورة المعاينة الحالية شعار المشروع؛ غيّر عنوان الصورة في layout وCSP إن نقلت الموقع إلى دومين جديد.
9. احتفظ بـdeploy السابق للرجوع بـ`pnpm exec wrangler rollback` عند الحاجة. rollback للكود لا يعكس بيانات D1. لا تعد إلى نسخة الثغرات القديمة إلا لمعالجة حادث مع تقييم أثره.

## حدود معروفة

- تجربة عامة محدودة: سقف سحابي حالي غرفتان بالتزامن؛ لا تعلن خدمة مفتوحة غير محدودة. كل منشئ يشغّل غرفة واحدة.
- LAN يتطلب Node 24.11+ ونسخة مجهزة من المشروع؛ لا يوجد installer محمول للمستخدم غير التقني بعد. رابط الموقع لا يثبت خادم LAN.
- لا يوجد انتقال آلي من cloud إلى LAN وسط اللعبة، ولا تحرير كامل للمسابقات دون إنترنت.
- الكاش والتحميل المسبق يحسّنان الإنترنت الضعيف؛ لا يضمنان تحميل صورة عبر اتصال مقطوع. LAN يعالج اعتماد الفعالية على WAN بعد تنزيل الحزمة مسبقاً، ويبقى معتمداً على Wi-Fi جيد ولابتوب مستيقظ.
- CSP تسمح inline scripts التي يحتاجها static Next؛ لا تدّع أنها تعوّض إزالة XSS أو أنها سياسة nonce صارمة. تشغيل LAN بـHTTP يكون على شبكة موثوقة فقط.
- رفع الصور يحتاج ضوابط استخدام ومراقبة. توقيع الرد يثبت الأصل والمعرف والنسخة؛ أبعاد وحجم الملف المرسلة من العميل ليست قياساً مستقلاً من Cloudinary Admin API.
- النسخ القديمة للصور والهوية لا تُحذف آلياً من Cloudinary حتى لا تتلف snapshots قديمة. راقبها ونظّف غير المرجع منها يدوياً بعد نسخ احتياطية.
