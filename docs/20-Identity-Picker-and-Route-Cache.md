# Identity picker and stale navigation fixes

The saved identity selector now uses compact segmented tabs, a search field, a separate management action, consistent image cards with a selection badge, and a footer that names the selection. Publication explanations remain in the existing confirmation dialog and selection notes instead of occupying an empty library. The compact skeleton uses the same gallery columns and artwork dimensions as the loaded cards. Empty messages appear only after a completed load; an empty stale response continues to show placeholders while refreshing.

The service worker previously cached Next.js client-navigation and prefetch payloads (RSC and exported index.txt) using cache-first. Those responses can revive an old studio bundle with no drag grips and old Arabic terminology even when full HTML navigations are network-only. Static cache v6 deletes the previous route cache, and all route/RSC/prefetch requests now use the network. Hashed assets and image caching remain available. Creator pages update an already-installed worker; subsequent registrations bypass the browser cache for the worker script. Existing open documents should be refreshed once to use the latest client bundle; editing forms are never reloaded automatically.

Validation: actual service-worker script executed in a VM against deliberately stale cached responses, confirming fresh document/RSC/prefetch reads, unchanged API handling, retained static-asset caching, and old cache deletion. Component rendering verifies an initial skeleton cannot show an empty-library message, while a resolved empty library does. Desktop and 390px browser checks cover selection, footer enablement, loaded card layout, and no horizontal overflow.
